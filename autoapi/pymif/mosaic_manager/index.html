Two tiles touch when their (z, y, x) boxes (Tile.extent) overlap or are less than tolerance apart on every axis (default: one voxel). Components are numbered by their position: by the y then x then z start of their bounding box, so the numbering does not depend on the tile order.

class pymif.mosaic_manager.MosaicManager(path: str | pathlib.Path)[source]

Bases: abc.ABC

A set of separately acquired, positioned tiles (not yet one image).

Unlike a MicroscopeManager, which wraps one image, a mosaic exposes the raw tiles lazily and fuses them on request with fuse(). Subclasses implement _scan() only.

Mosaics can be used as context managers so that open file handles are closed:

with mosaic_manager.LuxendoMosaicManager("raw_folder") as mosaic:
    mosaic.fuse("overview.ome.zarr", ds=(4, 8, 8), projection="max")

When loaded, every tile is labelled with the field it belongs to: tiles whose boxes overlap or touch form one field (a connected component), named field0, field1, … by position (see fields). fuse() fuses the first field by default; pick another with mosaic.fuse(out, field="field1"). Tiles of several fields are never fused together: that raises a MultipleFieldsError.

pymif.mosaic_manager.fuse_tiles(tiles: Sequence[pymif.mosaic_manager.tile.Tile], out: str | pathlib.Path, *, ds: Sequence[int] = (1, 1, 1), projection: str | None = None, blend: str = 'sigmoid', channels: Sequence[str] | None = None, channel_names: Sequence[str] | None = None, channel_colors: Sequence[str] | None = None, crop: dict | None = None, skip: Sequence[pymif.mosaic_manager.tile.Tile] | None = None, levels: int = 1, downscale_factor=2, workers: int = 1, executor: str = 'auto', out_dtype=None, midline_axis: str = 'x', sigmoid_steepness: float = SIGMOID_STEEPNESS, overwrite: bool = False, name: str | None = None, temp_dir: str | pathlib.Path | None = None, temp_compression: bool = False, progress: bool = True, **write_options)[source]

Fuse tiles into an OME-Zarr image and return it as a ZarrManager.

Parameters

tiles

Tiles to fuse (all must share voxel size and unit).

out

Output .ome.zarr path.

ds

(z, y, x) integer downsampling factors applied while reading the tiles (each output voxel is the mean of its block).

projection

None for a 3D volume, "max"/"sum" for a 2D projection along z.

blend

How tiles that overlap are merged:

  • "sigmoid" (default) – smooth transition: across an overlap, the share of each tile follows a sigmoid of the log ratio of the distances to the two tile borders, from 0 at a tile’s border through 1/2 in the middle of the overlap to 1 at the other tile’s border, so no seam is visible. The tiles of each group are fused separately, then the groups are merged the same way across their overlap along midline_axis (the switch is centred where "midline" cuts);

  • "max" – keep the brighter value;

  • "sum" – add the values, so overlaps show up as brighter bands;

  • "midline" – max within each tile group; where groups overlap, the image switches sharply from one group to the next at the middle of their overlap, along midline_axis.

channels

Tile channels to fuse, in output order. Default: all, in tile order.

channel_names, channel_colors

Names and colours (hex or matplotlib names) written for the output channels. Default: the tile channel names and the PyMIF palette.

crop

Part of the output to write, in output voxels (after ds), e.g. {"y": slice(100, 900), "z": slice(0, 50)}. For projections, a z crop limits the planes that are projected.

skip

Tiles to leave blank: they are not read, but the output keeps the size and position it has with them, so their area stays 0 (where no other tile covers it). With blend="midline"/"sigmoid" they still count for the position of the switch between groups.

levels

Number of pyramid levels.

downscale_factor

Factor between pyramid levels: one integer or (z, y, x).

workers

Number of regions fused in parallel (threads or processes, see executor).

executor

"process", "thread" or "auto" (processes when workers > 1 and every tile’s data is picklable, e.g. H5Array; threads otherwise). h5py serialises reads inside one process, so processes are what actually speeds up reading from HDF5 tiles.

out_dtype

Output dtype. Default: input dtype for sigmoid/max/midline, float32 for sum.

midline_axis

"x", "y" or "z": axis along which groups are separated (midline and sigmoid).

sigmoid_steepness

Steepness of the sigmoid transition (> 0). The share of a tile goes from 10% to 90% over the central 1 - 2 / (1 + 9 ** (1 / s)) of the overlap: about 27% for the default 4, 14% for 8, 50% for 2.

overwrite

Replace out if it exists.

name

Image name stored in the metadata.

temp_dir

Folder for the temporary fused level 0 (deleted at the end). Default: next to out. A local disk is faster when out is on a network share.

temp_compression

Compress the temporary level 0. Off by default: skipping compression (and decoding it again for the pyramid) is noticeably faster, but the temporary store then takes the full uncompressed size of level 0 (plan_fusion(...).nbytes), so temp_dir needs room for it. Turn it on when disk space is short.

progress

Show progress bars.

**write_options

Any other to_zarr() option, as for pymif convert: chunks, shards, shard_target_mb, shard_exclude_axes, zarr_format, ngff_version, compressor, compressor_level, drop_singleton, num_workers, storage_options. chunks is given in the output axis order (c, z, y, x, or c, y, x for projections).

The display window of every channel (OMERO window metadata) is set to the 0.5th-99.9th percentile of the fused values, ignoring blank areas, so viewers open the result with a usable contrast; see display_windows().

Use plan_fusion() with the same arguments to get the output shape and size without reading or writing anything.

tiles must come from one field (Tile.field, set by MosaicManager; skipped tiles count): tiles of separate fields are not fused, a MultipleFieldsError is raised before anything is read or written.

class pymif.mosaic_manager.LuxendoMosaicManager(path, scan_workers: int = 16, progress: bool = True)[source]

Bases: pymif.mosaic_manager.mosaic.MosaicManager

Raw Luxendo tiles (*.lux.h5 + *.json) of one acquisition, before any fusion.

Not to be confused with LuxendoManager, which reads images already fused by the Luxendo software. This manager scans a raw acquisition folder such as 2026-10-14_103957 (tiles live in raw/<stack folder>/Cam_*.lux.h5) and exposes every tile lazily:

  • channel: the dye, with the illumination side removed (autofluo-488-L and autofluo-488-R both give autofluo-488), so both halves of a sample end up in the same fused channel;

  • group: the illumination side, "L" or "R" (used by blend="sigmoid" and "midline");

  • timepoint: the JSON time_point (mosaics with several timepoints are refused for now, see MosaicManager);

  • attrs: stack, stack_description, grid ((ix, iy)), channel_description and path.

Tile positions come from affine_to_sample in the JSON (the tile is centred on the stage translation in x/y; z is the plane position along the stacking direction). If a stack was re-acquired (*_R_<n>.lux.h5) only the latest retake is used. Tiles are H5Array objects, so no file stays open. Scanning reads only the JSON files (in parallel) and opens a single .h5 file, which keeps loading fast on network drives.

class pymif.mosaic_manager.OperaFlatfield(mean: float, coefficients, dims=None, origin=None, scale=None)[source]

Harmony’s background flat-field correction of one channel (picklable).

Harmony describes the uneven background of a channel as a 2D polynomial P, normalised to a mean of 1, and its mean level Mean (FlatfieldProfile of the index, Background entry). It corrects every plane with:

raw >= Mean * P :  raw - Mean * (P - 1)    (above the background: remove its unevenness)
raw <  Mean * P :  raw / P                 (below it: rescale it to the flat level)

Both branches give Mean at raw = Mean * P. This reproduces the images stitched by Harmony to within rounding.

P(u, v) = sum_k sum_i c[k][i] * u**(k - i) * v**i, with u = (x - Origin[0]) * Scale[0] along image columns and v = (y - Origin[1]) * Scale[1] along rows, in the pixels of a Dims image (rescaled to the image size, e.g. for another binning).

class pymif.mosaic_manager.OperaMosaicManager(path, flatfield: bool = True, progress: bool = True)[source]

Bases: pymif.mosaic_manager.mosaic.MosaicManager

Raw Opera Phenix / Operetta (Revvity Harmony) tiles, before any stitching.

Not to be confused with OperaManager, which reads images stitched by Harmony (stitchresult/*.ome.tiff). This manager reads a Harmony export: Images/Index.xml and one TIFF file per plane (r01c03f01p01-ch1sk1fk1fl1.tiff: row 1, column 3, Opera field 1, plane 1, channel 1). Every Opera field of every channel is one tile; its planes stay on disk until read.

  • channel: the ChannelName of the index;

  • field: tiles are grouped per well into fields of touching tiles, named <well>_field<k> (A3_field0, A3_field1, …);

  • timepoint: TimepointID - 1 (mosaics with several timepoints are refused for now);

  • attrs: stack (r01c03f01, the tile id without the channel), well, row, col, opera_field, channel_id, flatfield and folder.

Geometry, consistent with the images stitched by Harmony: the x/y pixel size is the ImageResolution of the index scaled by the channel’s OrientationMatrix (a calibration of a few percent, which Harmony applies to its stitched images), tiles are centred on the field position, and stage y runs against image rows when the matrix says so (negative y scale). Planes are placed at their PositionZ, without the matrix’s z scale and offset.

Stage positions are relative to the centre of each well, so every well is shifted to its place on the plate (A1 at the top left, y along rows, x along columns), by the well pitch of the plate format (PlateRows x PlateColumns, see WELL_PITCH). The fused images do not depend on it.

With flatfield=True (default), every plane is corrected with the background flat-field profile stored by Harmony (see OperaFlatfield), as in the Harmony stitched images. The profiles are read from the index, or from FFC_Profile/*.xml next to Images/ when the index has none.
