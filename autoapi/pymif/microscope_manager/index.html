Abstract base class for managing microscope image datasets.

Provides shared functionality for reading, writing, visualizing, and managing multiscale image data and metadata.

Subclasses implement two hooks and inherit read():

  • _parse_metadata() – return the normalized metadata dictionary (see pymif.utils.metadata.build_metadata());

  • _build_dask_array() – return one lazy dask array per pyramid level.

Managers can be used as context managers so that any open file handle is closed automatically:

with mm.LuxendoManager("path/to/dataset") as lux:
    lux.to_zarr("out.zarr")

estimate_chromatic_shift(reference_channel: int = 0, **kwargs) → Dict[str, Any][source]

Estimate the axial (Z) chromatic shift of each channel of the raw image.

The shift is measured on the sample’s Z-facing surfaces (top and bottom), first on a coarse level and then on crops of a finer level. Keyword arguments are forwarded to estimate_chromatic_shift() (timepoint, coarse_level, refine_level, max_shift, n_regions, crop_yx, min_z_normal, min_correlation, threshold).

Returns a JSON-serializable report whose shifts entry holds the correction per channel in the physical unit of the Z axis; it can be passed directly to apply_chromatic_shift().

apply_chromatic_shift(path: str | pathlib.Path, shifts, *, extent: str = 'union', order: int = 1, include_groups: bool = True, include_labels: bool = True, overwrite: bool = True, num_workers: int | None = None, progress: bool = True) → ZarrManager[source]

Write a copy of this store with each channel shifted along Z.

Parameters

path

Output OME-Zarr store; must differ from the input.

shifts

One Z shift per channel in physical units (positive moves content towards higher Z), or the report of estimate_chromatic_shift().

extent

"union" (default) grows Z so no channel loses data, "same" keeps the input size and "intersection" crops to the planes covered by every channel. Padding is rounded to whole planes of the coarsest level so all pyramid levels stay aligned.

order

1 interpolates linearly; 0 rounds each shift to whole planes, which leaves voxel values untouched.

include_groups, include_labels

Also write image subgroups (shifted like the raw image) and labels (padded or cropped to the new Z extent, following the reference channel).

overwrite, num_workers, progress

Same meaning as in ZarrWriteConfig.

Every array keeps its source’s chunks, shards, codecs and dimension names, every group its attributes (pixel sizes, channel metadata…). Datasets must still match their on-disk arrays, so call this before in-memory edits such as subset_dataset().

Returns the output store opened as a new ZarrManager.

correct_chromatic_shift(path: str | pathlib.Path, reference_channel: int = 0, *, extent: str = 'union', order: int = 1, include_groups: bool = True, include_labels: bool = True, overwrite: bool = True, num_workers: int | None = None, progress: bool = True, **estimate_kwargs) → ZarrManager[source]

Estimate the Z chromatic shift and write the corrected store in one go.

Combines estimate_chromatic_shift() (estimate_kwargs) and apply_chromatic_shift(). The estimate report is stored in the output root attribute pymif_chromatic_shift.

Backward-compatible reader for legacy NGFF/OME-Zarr v0.4 stores.

The original implementation assumed five-dimensional TCZYX data. This compatibility wrapper now delegates to ZarrManager, which supports both v0.4 and v0.5 metadata layouts and any unique subset of the image axes t, c, z, y and x.
